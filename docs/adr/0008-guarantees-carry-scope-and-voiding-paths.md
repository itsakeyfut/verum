# Every AI Context key that claims a guarantee carries its scope and the paths that void it

## Context and Problem Statement

The strict goal — no bypasses — was judged unreachable (#45). The fallback the
owner accepted in its place is **accurate metadata with no lies**: bypasses are
tolerable if the artefact records them.

The artefact does record them. `unverified_boundaries` lists every path the type
check does not reach. But **nothing joins that list to the keys that claim the
guarantee**, and a consumer reads keys, not appendices. Someone who reads
`mutates.enforcement: "upper_bound_checked"` and stops has been told the
implementation is checked against the contract, and has not been told that the
check covers only calls routed through `ctx` inside `handle` — that a repository
implementation, a service body, middleware, a free-function constructor, or
`User::from_repr` can each change a field the key says will not change.

An adversarial read of the canonical example (`docs/specs/ai-context.md`)
produced five conclusions, all false. The pattern in them is specific:

> **The lies come from the mechanisms added in order to be honest.**

`observed` was added to supply a lower bound and now reads as "exactly these
fields change". `effective` was added to expand the declaration and, on the
`effects` object, expands nothing — it is a lookup on the HTTP verb. The
`forbidden` note was added to explain a weak enforcement level and instead
contradicts it. Meanwhile the plainest mechanisms — `enforcement`'s four values,
`escape_hatches: "unknown"` — work correctly.

What fails is **placing an unenforced assertion beside an enforced one in the
same shape.** The reader has no way to tell them apart, so the weak one borrows
the strong one's credibility.

## Decision Drivers

* The fallback criterion is the project's remaining acceptance test. If the
  metadata lies, nothing is left.
* One key already did this right: `scope_of_readonly_guarantee` was the only key
  that named its own scope. The fix is that idea generalised, not a new mechanism.
* `docs/specs/effect-inference.md` already argues the case for the *lower* bound —
  *"without `scope` an AI reads the lower bound as covering every path"*. The
  identical argument applies to the upper bound and had never been applied to it.
* A guarantee's honesty must not depend on the reader noticing a sibling key.
  That is the failure mode of `forbidden.note`, and it recurred with
  `effects.effective` beside `enforcement: "none"`.

## Considered Options

* **A. `enforcement` becomes `{level, scope, voided_by}`, with `voided_by` naming
  ledger `kind`s.**
* **B. Keep `enforcement` scalar; add a document-level `scope` block.** One place
  to maintain, but it restores exactly the gap being closed — the reader must
  leave the key to find the caveat.
* **C. Keep `enforcement` scalar; put the caveat in a `note` per key.** This is
  what `forbidden` already does, and `forbidden.note` is one of the five measured
  lies. Prose beside a label loses to the label.
* **D. Do nothing; the ledger is already published.** This is today's state, and
  the adversarial read is the evidence against it.

## Decision Outcome

Chosen: **A**.

```json
"enforcement": {
  "level": "upper_bound_checked",
  "scope": "handle_via_ctx",
  "voided_by": ["domain_repr", "repository_impl", "..."]
}
```

`level` keeps the four existing values. `scope` and `voided_by` are new, and both
are **generated by the framework, never hand-written** — they are constants of the
mechanism, not per-endpoint judgement, so they cost the contract author nothing.
That is what distinguishes them from `operation`, the field SRK-002 had removed
for guaranteeing nothing while being written every time.

**`voided_by` names `kind`s that appear in the same output's
`unverified_boundaries.entries`.** Raw path numbers (`"path_21"`) would not join;
`kind`s do. The artefact becomes self-joining, which is the entire point — the
consumer never has to leave it to learn where a guarantee ends.

`scope` is a **closed vocabulary** — `handle_via_ctx`, `declaration_only`, `none`
— for the reason `effect-system.md` gives for closing the infrastructure-effect
vocabulary: two spellings of one idea leave an AI unable to choose between them.

Where `level` is `metadata_only` or `none`, `voided_by` is the string
`"not_applicable"`, **never `[]`**. An empty array reads as "nothing voids this",
which is the strongest possible claim appearing on the weakest possible key.

### What follows from it

Five consequences are forced by the decision rather than chosen alongside it.

* **`scope_of_readonly_guarantee` is removed.** A GET's read-only guarantee is now
  stated exactly by `mutates` / `creates` / `deletes` being empty at
  `level: upper_bound_checked`, `scope: handle_via_ctx`, `middleware` in
  `voided_by`. A value derivable from its neighbours is a value that can disagree
  with them. It also overstated — a GET may cause Logging, Metrics, Tracing,
  CacheRead and CacheWrite — and was emitted on a `PUT` in the canonical example.
* **Paths 18 and 19 get `kind` names** (`constructor_body`, `upsert_granularity`).
  `voided_by` may only name a kind that exists, and both paths void `mutates`.
  The ledger's own counting rule already said "Decide both"; this forced it.
  Counts move 9 → 11.
* **`effects.effective` becomes `assumed_from_method`**, with `derived_from`. The
  name was the lie: `enforcement: "none"` sat beside it and readers still
  concluded the endpoint causes those effects.
* **`forbidden.note` loses "already uncallable"** — the setter exists and E0277 is
  what fails (RK-013), and path 21 forges the domain without a setter at all.
* **`unverified_boundaries` gains `completeness: "best_effort"`**, and `deferred`
  emits `"unknown"`. Both are the `escape_hatches` treatment: a list nobody can
  prove complete must not be published as though it were.

`model_fit` is added by the same reasoning but is not forced by it: a list,
search or aggregation endpoint emits JSON indistinguishable from a single-fetch,
and the model has no vocabulary for its shape (SRK-006). It emits `"unknown"`
today because nothing can determine it.

### Consequences

* Good: a consumer that reads one key learns the guarantee's strength, its
  reach, and what voids it, without leaving the key.
* Good: the honesty of the artefact stops depending on the reader's diligence.
* Bad: `voided_by` on `mutates` lists **nine of eleven** boundaries. That is
  accurate and it is unflattering; the whole design of the fallback criterion is
  that unflattering and accurate beats flattering.
* Bad: the schema is wordier per key, against `concepts.md`'s token-efficiency
  goal. Accepted — Q-B has not shown that goal to be met anyway, and a smaller
  artefact that misleads is worth nothing.
* Neutral: nothing is implemented, so this is not a breaking change to any
  emitter. It **is** a breaking change to `docs/rules/test.md`'s asserted fields,
  which is why they are updated in the same change.

## Confirmation

**This is none of the three defence layers.** Not macro, not equality bound, not
trait bound — do not read `diagnostics.md`'s layer table as covering it. It is
metadata plus a build-time check, the same category as the fourth mechanism the
Q-A decision introduced.

`spikes/doc-code-blocks/check_json.py` fails if:

* the string `type_checked` appears anywhere (`test.md` demanded this and nothing
  enforced it);
* an `enforcement` value is not an object with exactly `{level, scope, voided_by}`;
* `level` or `scope` falls outside its closed set;
* a `voided_by` names a `kind` absent from the ledger's own emitted entries —
  **the join is checked from both ends**, so neither side can rot alone;
* `escape_hatches`, `deferred` or `voided_by` is `[]`;
* `unverified_boundaries` is not an object carrying `completeness` and `entries`.

Each rule was broken on purpose and observed to fail before the checker was
adopted. A guard that has only been read is not known to work — the batting-average
log records two accepted findings missed that way on a shell guard.

What the checker **cannot** confirm is the part that matters most: whether the
canonical example still produces a false belief in a careful adversarial reader.
That remains a human pass, run on every change to the schema.
